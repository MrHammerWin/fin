## Реальный прогон на 50 ГБ

До запуска было свободно около 182,8 ГБ, что превышало установленный пользователем порог 100 ГБ. Генерация запущена через тот же HTTP-интерфейс фонового задания, который вызывает веб-форма.

| --- | ---: |
| Цель | 50000000000 байт |
| Размер после генерации | 50002841466 байт |
| Превышение при генерации | 2841466 байт |
| Допустимое превышение | 100000000 байт |
| Время генерации | 249 секунд |
| Исходные документы и реестры | 13276 файлов |
| Связанные обязательства | 52697202 |
| Строки данных CSV большого корпуса, без шапок | 212897698 |
| Файлы с независимо проверенной SHA-256 | 13276 из 13276 |
| Время независимой проверки файлов | 48,45 секунды |
| Размер после обновления интерфейса и очистки прежних наборов | 50002843069 байт |

Для каждого файла независимо проверены существование, фактический размер и SHA-256. Для всех CSV корпуса пересчитаны строки. Из каждого непустого реестра прочитан образец; для обязательств сверены ссылка на счёт/акт/договор и равенство «сумма − оплачено = остаток». На малом корпусе автоматический тест проверяет все связи и суммы по всем строкам и валютам.

Общий объём измерен по файлам внутри папки набора. После обновления шаблона при перезапуске немного изменился размер HTML; манифест и данные пересчитаны и снова совпадают с фактическим объёмом. Содержимое исходных реестров осталось прежним. Большой набор и локальные исходники OCR не включаются в Git.

## Проверка в браузере

В браузере проверены страницы конвертера, генератора и документов, переключение источника, конвертация существующего DOCX в CSV, загрузка отдельного пользовательского CSV и его конвертация в XLSX. У результата есть ссылка на скачивание и предупреждение. Проверены параметры объёма, фактический размер датасета, кнопка «Обновить размер» и переход списка файлов со страницы 1–25 на 26–50.

После последней доработки проверены отсутствие отдельной кнопки на главной, переход в генератор, кнопка «Сгенерировать и заменить», описание замены и размер 50,003 ГБ при 13282 файлах. По выбору пользователя единственным рабочим набором оставлен существующий набор на 50 ГБ. После перезапуска в рабочей папке остался один датасет, прежний малый набор и исходная рабочая копия удалены; API не сообщает ошибок очистки. Снимок интерфейса и результаты проверки сохранены локально в `.test-artifacts/`.

HTTP-тест подтверждает, что старый набор удаляется, ссылки его страниц открывают текущий, а измерение замечает изменение файлов после генерации. Отдельно проверены сохранность текущего при ошибке/отмене, очистка ранее накопленных наборов при запуске, сохранение посторонних файлов и повторная очистка после сбоя.

## Границы проверки

Нативные проверки выполнены на macOS с .NET SDK 10.0.402, локальными LibreOffice, Poppler и Tesseract с русской и английской моделями. Windows локально не запускалась. В GitHub Actions добавлена матрица macOS/Windows с установкой движков и запуском нативных проверок; её результат нужно оценивать по конкретному запуску CI.

OCR может ошибаться в символах и числах. Из PDF восстанавливается приближённая структура, а не исходные формулы и вёрстка. Предупреждения выводятся пользователю. Большой корпус не выдаётся за импортированный в календарь: календарь и отчёты показывают отдельный контрольный пример.

| Документация, CI и исключения Git | Запуск на двух ОС, проверка и исключение больших/пользовательских файлов из репозитория |
